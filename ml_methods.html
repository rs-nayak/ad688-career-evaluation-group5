Predictive Modeling

This page groups all Data Scientist postings in NAICS 5417 into market segments using unsupervised learning (K-Means, with PCA for visualization). The goal is to see what kinds of postings exist in the market so we can compare them with our own skill profiles.

Feature Preparation

We use the cleaned posting panel from the Data Preparation page and keep all postings. Salary is listed on only about a third of them, so it is not used to form the segments. Instead, segments are built from minimum years of experience, the number of listed skills, the number of software skills, and the work arrangement. Where minimum experience is missing, we fill it with the median and add a flag for “experience listed,” so those postings stay in the model. Salary is then compared across segments, using only the postings that list it.

df = pd.read_csv("output/career_market_panel.csv")

def count_items(x):
    """Skill columns are saved as list-like strings in the CSV."""
    if isinstance(x, (list, tuple)):
        return len(x)
    if pd.isna(x):
        return 0
    try:
        v = ast.literal_eval(str(x))
        return len(v) if isinstance(v, (list, tuple, set)) else 1
    except (ValueError, SyntaxError):
        s = str(x).strip("[]")
        return len([p for p in s.split(",") if p.strip()])

df["n_skills"] = df["skills_array"].apply(count_items)
df["n_software_skills"] = df["software_skills_array"].apply(count_items)
df["exp_listed"] = df["min_experience_years"].notna().astype(float)
df["exp_filled"] = df["min_experience_years"].fillna(df["min_experience_years"].median())
df["remote_type_clean"] = df["remote_type_clean"].fillna("Unknown")

work = pd.get_dummies(df["remote_type_clean"], prefix="work", dtype=float)
X = pd.concat([df[["exp_filled", "exp_listed", "n_skills", "n_software_skills"]], work], axis=1)
X_scaled = StandardScaler().fit_transform(X)

print(f"Postings listing minimum experience: {int(df['exp_listed'].sum()):,}")
print(f"Features: {list(X.columns)}")

Choosing the Number of Clusters

We fit K-Means for k = 2 to 8 and compare inertia (elbow) and silhouette score.

rows = []
for k in range(2, 9):
    km = KMeans(n_clusters=k, n_init=10, random_state=RANDOM_STATE).fit(X_scaled)
    rows.append({"k": k, "inertia": km.inertia_,
                 "silhouette": silhouette_score(X_scaled, km.labels_)})
k_scores = pd.DataFrame(rows)

fig = px.line(k_scores, x="k", y="silhouette", markers=True,
              title="Silhouette score by number of clusters")
fig.update_layout(xaxis_title="Number of clusters (k)", yaxis_title="Silhouette score")
fig.show()
fig = px.line(k_scores, x="k", y="inertia", markers=True,
              title="Elbow plot: inertia by number of clusters")
fig.update_layout(xaxis_title="Number of clusters (k)", yaxis_title="Inertia")
fig.show()

Interpretation: The silhouette score keeps rising from k = 2 to k = 8 (about 0.28 to 0.48) and never peaks, and the elbow plot has no sharp bend, so the data do not point to one “correct” k. We fixed k = 5 because it gives five segments that are large enough and different enough to describe, with a silhouette score of about 0.40. This is a judgment call, not a statistical optimum.

Market Segments

Segments are numbered from largest (1) to smallest (5), so the numbering stays the same if the model is rerun.

km = KMeans(n_clusters=K, n_init=10, random_state=RANDOM_STATE).fit(X_scaled)
df["cluster"] = km.labels_
order = df.groupby("cluster").size().sort_values(ascending=False).index
df["segment"] = df["cluster"].map({old: str(i + 1) for i, old in enumerate(order)})

pca = PCA(n_components=2, random_state=RANDOM_STATE)
coords = pca.fit_transform(X_scaled)
df["PC1"], df["PC2"] = coords[:, 0], coords[:, 1]
var = pca.explained_variance_ratio_ * 100

fig = px.scatter(

)
fig.update_layout(xaxis_title=f"PC1 ({var[0]:.1f}% of variance)",

Salary by segment

Salary is shown only for postings that list it, so each box rests on far fewer postings than the segment size above.

sal = df.dropna(subset=["annual_salary_midpoint"])
fig = px.box(sal, x="segment", y="annual_salary_midpoint", color="segment",
             category_orders={"segment": sorted(df["segment"].unique())},
             title="Salary distribution by segment (postings that list a salary)")
fig.update_layout(xaxis_title="Segment", yaxis_title="Annual salary midpoint (USD)",
                  showlegend=False)
fig.show()

Interpretation: The segments are shaped mostly by how a posting states its work arrangement and whether it lists experience, not only by the type of role. Segment 1 (261 postings) does not state a work arrangement, always lists experience (median 0 years), and has shorter skill lists (about 6.8 skills); its median salary is about $200K. Segment 2 (170) is all hybrid, at about $186K. Segment 3 (150) is all remote, at about $187K. Segment 4 (128) does not state a work arrangement and almost never lists experience, but has full skill lists (about 9.8), at about $200K. Segment 5 (51) is all on-site and is the lowest paying, at about $126K. For an early-career team, Segment 1 is the clearest fit because every posting lists experience and the median requirement is 0 years, and Segment 3 is the remote option at a similar pay level to the hybrid group.

What This Analysis Means for a Job Seeker

  • What was modeled: All 760 Data Scientist postings in NAICS 5417 were grouped into five segments with K-Means, so a job seeker can see what kinds of postings the market offers.
  • Why it matters: The segments show how work arrangement, experience requirements and listed pay differ across the market, which helps a candidate decide where to apply first.
  • Variables used: Minimum years of experience (with a flag for postings that do not list it), number of listed skills, number of software skills, and work arrangement. Salary was left out of the grouping because only 240 of 760 postings list it, and is compared across segments afterward.
  • How it was evaluated: There is no single correct answer to compare against, so we used the silhouette score (about 0.40 at k = 5), the elbow plot, and a profile table checking that each segment is distinct and large enough to describe.
  • What it means in practical terms: In this sample, postings that list experience at 0 years (Segment 1) and remote postings (Segment 3) look most accessible to an early-career applicant. On-site postings that list a salary pay noticeably less (about $126K, from only 20 postings). Applicants should treat these as starting points to check against the posting itself, not guarantees.

Limitations

  • Salary is listed on only 240 of the 760 postings, and each segment’s salary figures rest on 20 to 58 of them, so small differences between segments are not reliable.
  • Missing minimum experience was filled with the median and flagged, so the experience values for those postings are not real data.
  • The choice of k = 5 was a judgment call, because the silhouette score did not peak.
  • Salary is the posted range midpoint, not actual pay.
  • Clusters describe patterns in postings; they do not say which role is best for any one person.
